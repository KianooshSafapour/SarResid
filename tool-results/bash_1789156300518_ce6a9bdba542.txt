Platform: Next.js 16 (App Router, single `/` route, client-side hash router) + TypeScript + Prisma/SQLite + Tailwind 4 + shadcn/ui + sonner + socket.io mini-service.

## Conventions established (KEEP THESE)
- **UI is 100% Persian RTL**, formal but friendly, touch-first (big buttons, steppers, PIN pad login).
- All dates are Jalali. Use `src/lib/jalali.ts` (faNum, faMoney, formatJalaliShort/Long/Full/DateTime, toJalaliParts, jalaliToIso, addDaysIso, daysBetween, jMonthLength, jMonthStartWeekday, todayIso).
- Shared UI in `src/components/app/ui-bits.tsx`: `AppCtx` type, SectionCard, StatCard, Pill, EmptyState, Avatar, stockStatus, SearchInput, Labeled, KeyValue, CATEGORY_EMOJI.
- Charts: `src/components/app/charts.tsx` (BarChart, LineChart, Donut, RankBars).
- Jalali widgets: `src/components/app/jalali-widgets.tsx` (JalaliCalendar, JalaliDatePicker, useHolidays hook).
- Client fetch: `api<T>(path, {method, body})` from `src/lib/client.ts`. Toasts: `toast` from sonner.
- Modal component is exported from `src/components/views/Orders.tsx` (`import { Modal } from '@/components/views/Orders'`).
- View props signature: `export default function XView({ ctx }: { ctx: AppCtx })`.
- Colors: emerald #0e7a4a primary, gold #c9a227, terracotta #c96f4a, olive #77934a, rose #b3372f, bg cream #faf7ee, sidebar deep emerald #0b2e20 with `.pattern-girih`, cards use `.glow-card .gold-glow-border`. NO blue/indigo as primary. Use class `scroll-gold` on scrollable lists, `fade-in-up` on sections.
- API helpers: `src/lib/api-helpers.ts` (getSessionUser(req), json, fail, logActivity, appendHistory, safeParse).
- Constants/labels: `src/lib/constants.ts` (ROLE_LABELS, ORDER_STATUSES, CHEQUE_STATUSES, TASK_STATUSES, PRIORITIES, VIEW_ACCESS, canAccess).
- DB: `import { db } from '@/lib/db'`. No list primitives in Prisma — JSON strings + safeParse.
- Every mutation should call `logActivity(me, 'action', entity, entityId, detail)`.

## API contract cheat-sheet for view builders
- Tasks: GET /api/tasks?scope=mine|all → {tasks}; POST {title,description,type,priority,assignedToId,dueDate,points}; PATCH /api/tasks/[id] {action:'start'|'pause'|'done'|'reopen', pauseNote} → {task, awarded} (done auto-awards points); DELETE /api/tasks/[id].
- SOPs: GET /api/sops → {sops:[{steps:[{title,detail}]}]}; POST {title,category,steps:[{title,detail}]} (managers); PATCH {id,title,category,steps}; DELETE ?id=.
- Wall: GET /api/wall → {posts}; POST {title,content}; DELETE ?id=.
- Notes: GET /api/notes → {notes} (private); POST {content,color}; PATCH {id,content,color,pinned}; DELETE ?id=.
- Feedback: GET /api/feedback → {feedback, canManage}; POST {type:'ANON'|'IDEA', content, anonymous}; PATCH {id,status,response,points} (managers; points>0 awards idea owner).
- Planograms: GET /api/planograms → {planograms:[{layout:[[productId|null]]}], productMap:{id:{name,stock,reorderLevel,category}}}; POST {name,section,rows,cols}; PATCH [id] {layout,status:'PUBLISHED'}; DELETE [id].
- Refill (merchandiser → storekeeper): create Task via POST /api/tasks with type 'TASK' assigned to SK user, or use customer-requests? No — RefillRequest model exists but no dedicated route yet; use tasks instead.
- Sales: customers GET/POST/PATCH /api/customers; preorders GET ?scope=all|mine|cashier, POST {customerId,customerName,items:[{productId,name,qty,price}],note}, PATCH [id] {action:'cashier_edit'|'done'|'cancel', items}.
- Customer requests: GET /api/customer-requests; POST {productName,productId,notes} (increments count if same name); DELETE ?id=.
- Gamification: GET /api/gamification → {leaderboard, awards, recentAwards, stats, badges}; POST /api/gamification/award {userId,points,reason} (managers).
- Admin: users GET/POST /api/users, PATCH/DELETE /api/users/[id]; activity GET /api/activity?entity=&q=; holidays GET/POST/DELETE /api/holidays, POST /api/holidays/sync.
- Dashboard: GET /api/dashboard → {kpi, series, chequeSeries, overdueOrders, todayDeliveriesList, lowStockList, leaderboard, wall, activities, customerReqs, myTasks, toAccount, pendingChequesList}.
