# تاب‌آوری سامانه SarResid — Resilience & No-SPOF

**هدف:** هیچ‌گاه تکرار نشود؛ نه سرور بی‌سرپشت بماند، نه داده و نه کد از دست برود.

## سه لایهٔ دفاع

| لایه | مکانیزم | ریتم | محل |
|------|---------|------|-----|
| ۱ — خودترمیمی | `scripts/watchdog.ts` هر ۴۵s به `/api/health` ضربه می‌زند؛ ۳ خطای پیاپی = ری‌استارت خودکار `bun run dev` | 45s | مستقل از Next |
| ۲ — پشتیبان آنلاین | `VACUUM INTO` (اسنپ‌شات سازگار وسط تراکنش) + `PRAGMA integrity_check` | 10 min | `db/backups/auto/` (۱۲ نسخه) + آینهٔ `~/sarresid-backups/auto/` |
| ۳ — اسنپ‌شات کد | `git add -A && git commit` در صورت وجود تغییر | 3 h | تاریخچهٔ گیت |

## اجرا
```bash
nohup bun scripts/watchdog.ts > /dev/null 2>&1 &   # شروع نگهبان
tail -f logs/watchdog.log                          # تماشای ضربان
curl -s localhost:3000/api/health                  # سلامت لحظه‌ای
```

## قواعد ضد-تک‌نقطه-شکست
1. **اسکیمای Prisma فقط توسط کارگردان اصلی و یک‌بار در هر دور** تغییر می‌کند و `db:push` می‌شود — عامل اصلی سانحهٔ راوند ۱۹ (push همزمانِ چند ایجنت) برای همیشه ممنوع است.
2. هر ایجنت موظف است **قبل از کار، وسط کار و بعد از کار** در `worklog.md` بنویسد؛ از دست رفتن دانش ممنوع.
3. پایان هر موج = **anchor commit** در گیت (نقطهٔ بازگشت شماره‌دار).
4. پشتیبان همیشه دو جا می‌نشیند: داخل پروژه + بیرون آن (`~/sarresid-backups`).
5. حذف دستی `db/custom.db`، پاک‌سازی کامل (بخش مدیریت داده) و restore هرگز قبل از یک پشتیبان خودکار تازه انجام نمی‌شود.

## بازیابی از حادثه
```bash
# بازگرداندن آخرین پشتیبان سالم:
cp db/custom.db db/custom.db.broken && cp db/backups/auto/<file>.db db/custom.db && bun run db:push
# بازگرداندن کد از آخرین اسنپ‌شات:
git log --oneline -5 && git checkout <sha> -- src/
```
